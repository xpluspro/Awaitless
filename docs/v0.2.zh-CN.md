# Awaitless v0.2：Agent 原生调用与调度集群支持

## 一句话验收标准

用户安装 PyPI 包、配置一个 MCP Server 后，Agent 无需手写 Awaitless CLI，
就能在 Slurm 集群提交任务、断线恢复并获得结构化结果。

## 发布范围

v0.2 只包含两个主题：

1. 标准 stdio MCP Server，提供 `submit_job`、`wait_for_job`、
   `get_job_status`、`get_job_logs`、`cancel_job`、`list_jobs`。
2. Slurm backend，通过 SSH 使用调度器完成提交、恢复、状态/退出码映射和取消。

在 `[defaults]` 同时设置 `backend="slurm"` 与 `host="cluster"` 后，Agent 调用
`submit_job` 时无需重复给出 backend 或 host。

MCP 工具直接创建现有 `Service`；任务、状态事件和 Slurm ID 继续写入同一 SQLite
数据库。没有常驻 Awaitless daemon、HTTP API 或 Web 服务。

## 执行边界

```text
Agent
  └─ stdio MCP client
       └─ awaitless-mcp
            └─ existing Service + SQLite
                 ├─ SSH control: sbatch / squeue / sacct / scancel only
                 └─ SFTP data: private job directory, bounded logs, JSON Artifact
                                      │
                                      └─ Slurm allocated compute node runs user command
```

- `sbatch --parsable` 接收 stdin batch script 并返回持久化 scheduler ID。
- `squeue` 只查询仍活跃的作业。
- 作业离开队列后，`sacct --allocations --parsable2` 返回终态、`ExitCode` 和
  `ElapsedRaw`；accounting 短暂延迟由可配置 grace window 处理。
- `scancel` 是唯一取消路径。
- SSH 控制命令有代码级白名单，无法把用户命令改写成登录节点 shell 进程。
- SFTP 是独立文件数据通道，读取时先取文件大小，再只传输配置预算内的尾部；
  预算内的 JSON Artifact 会解析为 `parsed_results`。

上述行为对应 Slurm 官方的
[`sbatch`](https://slurm.schedmd.com/sbatch.html)、
[`squeue`](https://slurm.schedmd.com/squeue.html)、
[`sacct`](https://slurm.schedmd.com/sacct.html)、
[`scancel`](https://slurm.schedmd.com/scancel.html) 与
[`Job State Codes`](https://slurm.schedmd.com/job_state_codes.html) 契约。

## 状态与退出码

| Slurm | Awaitless | 说明 |
|---|---|---|
| `PENDING` / requeue/hold | `pending` | 等待资源或重新排队 |
| `RUNNING` / `CONFIGURING` / `COMPLETING` 等 | `running` | 已分配或正在收尾 |
| `COMPLETED` + `0:0` | `succeeded` | 成功 |
| `CANCELLED` | `cancelled` | 用户或管理员取消 |
| `TIMEOUT` / `DEADLINE` | `timed_out` | 调度器时间边界 |
| `FAILED` / `NODE_FAIL` / `OUT_OF_MEMORY` / `PREEMPTED` 等 | `failed` | 保留退出码与原因 |

`N:S` 形式的 Slurm `ExitCode` 会保留普通退出码；当普通退出码为 0、信号为
`S` 时，返回进程惯例的 `128 + S`。

## 真实验收记录

2026-08-10 在 `xflops_sy` 对应的 Slurm 25.11.2 集群执行了
[`scripts/mcp_slurm_demo.py`](../scripts/mcp_slurm_demo.py)：

1. 客户端 1 调用 `submit_job`，得到 Awaitless ID
   `job_019FE9CB2847AC929E0B2F` 和 Slurm ID `60597793`，随后退出。
2. 客户端 2 在独立 stdio 会话中只携带 Awaitless ID 调用 `wait_for_job`。
3. 返回 `succeeded`、退出码 0、`duration_seconds=8.0`、43 B stdout，且
   `truncated=false`。
4. stdout 和 JSON Artifact 都报告 `compute_host=node099` 与
   `slurm_job_id=60597793`，证明用户命令在调度获得的计算节点执行。
5. Artifact 被解析为结构化 `parsed_results`。
6. 另一个双客户端实测将 Awaitless `job_019FE9D0CA30EF2A8B018C` / Slurm
   `60598011` 提交后断开，再由新客户端调用 `cancel_job`；`scancel` 成功并返回
   `cancelled`。

原始机器可读记录位于
[`assets/mcp-slurm-demo.json`](../assets/mcp-slurm-demo.json)。
